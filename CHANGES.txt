=====================================================================
DECISIONS AND DIFFERENCES FROM THE ORIGINAL BRIEFS
=====================================================================
  * Accent colour is blue (#1d4ed8), not purple/indigo, after the earlier
    colour commits. Only existing tokens are used, plus the amber trio above.
  * Case Studies are a list of rows, not a card grid, so the thumbnail strip
    sits at the bottom of each row.
  * There is no Playbook page or "Pre-Flight Confluence Gate" in this repo, so
    the checklist reuses the existing case-study checklist rows and the existing
    win / loss pill classes. There is also no "+ Add New Setup" button, so Edit
    Entry uses the "New Trade" primary button size.
  * There is no outlined-destructive button in the app; Delete Log is a new
    variant built from the existing error tokens.
  * Setup Used is always "Not recorded" (no setup entity exists). Funding / OI /
    liquidation factors do not exist in the data.
  * "Breakeven" is not a form option; it only appears for zero-P&L imports and
    is now shown neutrally.


=====================================================================
VERIFICATION AND KNOWN LIMITS
=====================================================================
Checked
  * Syntax check of app.js (JavaScriptCore)
  * 34 + 53 logic checks: migration, tabs, strip, checklist statuses, session /
    duration helpers, renderCaseStudy output, status-click persistence,
    delete-modal open / close / focus trap / confirm, GitHub payload shape
  * Every #cs-* id used by the JS exists exactly once in index.html; the whole
    document is tag-balanced

NOT checked (no browser could be launched in the working environment)
  * Visual layout, spacing, column proportions, amber tag contrast
  * Real file upload, drag-and-drop and canvas compression
  * Tab clicks and the zoom viewer in a real browser
  * Live GitHub sync round trip

Known limits
  * All data still lives in one localStorage key (about 5MB per origin);
    compression reduces the risk but does not remove the ceiling.
  * The case-study list decodes three inline images per row, which may be slow
    with many trades.
  * Old images/<id>.<ext> files in a GitHub data repo are left as orphans.
  * GitHub pull now aborts on a network error while fetching an image instead of
    silently dropping it.
  * Confluence Matrix and Insights ignore the new Passed / Pending / Failed status.
  * Duplicate and Export PDF Study buttons remain unwired.
  * Session is calculated with the current timezone setting, not the one in
    effect when the trade was logged (same behaviour as Timing & Heatmap).
